Insecure Transmission Channel

Alice & Bob Wiretap

Disposable communication channel simulating an untrusted wire. Payloads are encrypted locally client-side before transmission. Any peer connected to the channel acts as Eve, inspecting intercepted payloads with the trace engine.

System Architecture & Threat Model

Operational constraints, memory guarantees, and client boundaries
Client-Side Boundary
Plaintext does not cross the network unencrypted when an active cipher is configured. Modular substitutions, matrix operations, and key schedules execute inside browser memory prior to socket dispatch.
Volatile RAM Persistence
Relay channels reside strictly in application process memory. Zero disk, SQLite, or file persistence is maintained. Once channel participants disconnect, session tokens and message queues are purged immediately.
Payload Inspection Engine
Every relayed transmission carries character trace metadata. Peers can open the inspector on any message to review the exact modular operations, key parameters, and inverse transformations applied.
Implementation Notes & Engineering Caveats
  • Hill Cipher Alphabet Modulation: The client-side educational trace visualizes the classical Latin alphabet modulo 26 for readability. The backend engine in crypto/hill.py utilizes a 97-character prime alphabet to ensure mathematical invertibility across ASCII spaces and special characters.
  • AES Implementation Architecture: AES-256 is implemented from raw mathematical principles in pure Python (Galois field multiplication in GF(2^8), Rijndael key expansion, round state transformations) without invoking third-party cryptographic library wrappers.
  • Quantum Simulation Bounds: BB84 simulation models idealized state preparation and detection. Optical attenuation, dark count detector noise, and polarization alignment drift are omitted in favor of clear state collapse visualization.
